## Hidden-Feature Revalidation

Searches were run for routes, exported methods, staff capability maps, schema tables, CLI endpoints, and blocked markers (`501`, `not_configured`, `ApiUnavailableError`, `TODO`, `FIXME`, `not implemented`, `return []`, `available: true`, `synthetic`, `hardcoded`, `unsupported`, `disabled`). Findings:

- Real web API methods have matching control-plane routes and visible UI/CLI callers, except runtime computer/files/logs/terminal and CLI-engine state, which are explicitly `NOT_PRODUCTIZED_BLOCKED`.
- Customer-safe routes without UI callers were not found among current protected customer routes; CLI-only endpoints are documented as CLI/PAT surfaces.
- Admin routes with mutation authority are all behind `admin.*` capability gates and have Admin navigation entries.
- Support routes are limited to search, detail, and add-note and have Support navigation entries.
- `return []` hits are valid empty-result semantics or fail-closed gateway behavior, not fake successful data.
- `available: true` hits are catalog/price availability derived from seeded catalog data, not blanket runtime availability.
- `synthetic` hits in tests/comments describe regressions avoided; the product no longer depends on client-only synthetic ids for routes.
- No visible capability looks enabled while deterministically failing with an unexplained 501; blocked surfaces render explicit unavailable/not-configured copy.
